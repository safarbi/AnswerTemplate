# Курс: Claude и Claude Code до уровня профессионала

Все практики делаются на проектах этого репозитория: разбор коллизий,
спецификация из Revit, окупаемость мероприятий.
Одно задание рассчитано на один помодоро.

| Уровень | Тема | Практика | Готово |
|---|---|---|---|
| 1 | Постановка задачи: цель, контекст, формат, критерий готовности | Переписать свой запрос по коллизиям по формуле | да |
| 2 | Claude Code в работе: план, разрешения, откат через git | Добавить правило в правила.csv через режим плана | пропущен |
| 3 | Память и контекст: CLAUDE.md, память Notion, /clear и /compact | Дописать своё правило работы в CLAUDE.md | нет |
| 4 | Свои команды: скиллы и хуки | Сделать команду «разбор коллизий» одной фразой | нет |
| 5 | Подключения: MCP, Notion, Gmail, GitHub, артефакты | Отчёт по коллизиям страницей, которой можно поделиться | нет |
| 6 | Масштаб: субагенты, параллельная работа, Claude в GitHub | Разобрать несколько отчётов параллельно | нет |
| 7 | Профессиональные привычки: проверка, безопасность данных, выбор модели | Итоговый проект от запроса до pull request | нет |

## Правила курса
- Сначала практика, теория не больше пяти минут.
- Каждое выполненное задание фиксируется коммитом: «Курс: уровень N, что сделано».
- Не идёт, уменьшить задание, а не бросать.

## Уровень 1. Постановка задачи

Формула хорошего запроса:
1. **Цель.** Что должно получиться.
2. **Контекст.** Что Claude должен знать: файлы, нормы, ограничения.
3. **Формат.** В каком виде нужен результат.
4. **Критерий готовности.** Как понять, что задача решена.

Плохо: «разбери коллизии».

Хорошо: «Разбери коллизии из отчёта Navisworks в файле отчёт.xml.
Это раздел ОВ против КР, допуск по BEP 10 мм, проходы через стены
оформляем заданием на отверстие. Результат нужен таблицей для Excel
с пометкой и причиной. Готово, когда каждая коллизия помечена и
ни одна не осталась без причины».

## Уровень 3. Память и контекст

Claude не помнит прошлые разговоры. Всё, что он знает в сессии,
лежит в контексте: ваши сообщения, его ответы, прочитанные файлы.

Три слоя памяти:
1. **Контекст сессии.** Живёт до конца разговора. Команда `/clear` начинает с чистого листа,
   `/compact` сжимает длинный разговор в краткую выжимку.
2. **CLAUDE.md.** Файл в репозитории, Claude читает его при старте каждой сессии.
   Здесь правила проекта. Команда `/init` создаёт черновик по коду, `/memory` открывает файл для правки.
3. **Память Notion.** Сведения о человеке, которые нужны в любом проекте и приложении.

Где что хранить:
- Правило конкретного проекта, например допуск коллизий: CLAUDE.md этого проекта.
- Сведения о себе, цели, стиль общения: память Notion.
- Временное, например «сегодня работаем с П1»: просто напишите в чате.

Практика: добавить своё правило в CLAUDE.md через GitHub и проверить его в новой сессии.
